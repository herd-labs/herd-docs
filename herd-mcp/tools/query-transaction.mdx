# Transaction Tools

Transaction Tools inspect individual transactions across all registered EVM chains. On fully indexed chains, they also search recent decoded function calls and event emissions.

## Available tools

| Tool | Use it to | Chain availability |
|---|---|---|
| `queryTransactionTool` | Decode traces, logs, transfers, balance changes, and contract creations for one real or simulated transaction. | All registered EVM chains |
| `queryTevmFork` | List every transaction recorded on a specific HAL simulation fork with its action, execution, batch, and step context. | All registered EVM chains |
| `getLatestFunctionTransactionsTool` | Find recent decoded function calls for a contract, optionally filtered by function name or four-byte selector. | Base, Ethereum, Monad |
| `getLatestEventTransactionsTool` | Find recent decoded event emissions, optionally filtered by event name, topic hash, and indexed topics. | Base, Ethereum, Monad |

`queryTransactionTool` can return all decoded data or filter balances, traces, and logs with a natural-language query. Transfer and balance amounts are decimal-adjusted; trace and log values remain raw.

For simulated hashes, pass the `tevmForkId` returned by HAL. The same deterministic hash can exist on more than one fork, so the fork ID identifies the exact simulation state.

## Indexed contract activity

Function and event searches return the latest 20 matching transactions. Use a function or event name to resolve its signature from the contract ABI, or pass the selector or topic hash directly.

Argument values are raw rather than decimal-adjusted. Use contract metadata and ABI types to interpret units and structure.

<Tip>
  Before authoring a HAL action, inspect recent calls and events. Real transactions reveal approvals, parameter patterns, and multi-step flows that an ABI cannot show.
</Tip>

## Common uses

- Confirm which contracts and functions a transaction called.
- Find token approvals, Permit2 signatures, and prerequisite steps.
- Inspect internal calls, decoded events, and asset movement.
- Verify that a simulation used gas, emitted logs, or transferred assets.
- Connect a simulated call back to its HAL batch and step.

<Warning>
  A successful simulation can still call an address with no deployed code. Treat zero gas with no calls, logs, or transfers as evidence that nothing ran.
</Warning>
