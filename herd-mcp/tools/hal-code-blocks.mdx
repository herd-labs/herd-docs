# Code Blocks

Code blocks run typed TypeScript for logic that is awkward or unavailable in HAL itself. Herd deploys the code, extracts its input and output schemas, and creates a synchronized adapter for use in actions.

## Available tools

| Tool | Use it to |
|---|---|
| `halGetCodeBlockTool` | List code blocks or read one definition, its selected code version, schemas, and version history. |
| `halCreateCodeBlockTool` | Deploy a new TypeScript code block and generate its synchronized adapter. |
| `halUpdateCodeBlockTool` | Change metadata or code, redeploy it, and optionally publish the latest draft. |
| `halExecuteCodeBlockTool` | Run a selected or latest code version with typed arguments and optional logs. |
| `halDeleteCodeBlockTool` | Delete a definition and its synchronized adapter when nothing imports it. |

Code must use `@herd-labs/code-blocks-framework` and export the framework server's `fetch` handler. The declared input and output schemas become the adapter's HAL types.

## Lifecycle

1. Create the code block with its name, TypeScript source, and optional intent.
2. Execute the test deployment with representative inputs.
3. Review logs when debugging, then disable log collection for faster calls.
4. Publish the version before importing its adapter into an action.

When you update published code, Herd creates a new draft. When the latest version is already a draft, Herd updates that draft in place.

<Warning>
  Do not edit or delete the generated adapter directly. Change the owning code block so the adapter and schemas stay synchronized.
</Warning>
