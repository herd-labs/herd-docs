# Herd Action Language

<Info>
  **Adapters** package reusable reads and call construction. **Actions** package transaction batches. Add them to **collections** so teams and agents can share, discover, and simulate complete workflows. Herd agent wallets can then propose action transactions to a Safe or another MPC wallet while the wallet keeps its signing and execution policy.
</Info>

HAL is a typed, JSON-based expression language for blockchain interactions. Its Scheme-inspired syntax is easy for agents to generate and safe for Herd to validate before execution.

Every HAL expression is valid JSON:

```json
["add", 1, 2]
```

Arrays represent calls or special forms. Objects evaluate their values recursively. Strings resolve to scoped variables when a binding exists and otherwise remain literal strings.

## Core syntax

| Form | Purpose |
|---|---|
| `do` | Evaluate expressions in sequence and return the last result. |
| `define` | Bind a value or define a typed function. |
| `import` | Load functions from a standard module or a published action or adapter. |
| `export` | Expose the entry point that callers can use. |
| `if` | Evaluate one of two branches. |
| `for-each` | Plan one inline batch step for each list element. |
| `quote` | Keep literal arrays, such as ABI parameters, from being evaluated as calls. |
| `coerce` | Validate and convert a result to a HAL type. |

HAL supports Solidity ABI types, tuples, arrays, unions, `any`, and `float64`. Integer values remain exact and are commonly represented as decimal strings at API boundaries.

## Standard modules

- `herd` provides blockchain reads, storage access, calldata encoding, write planning, swaps, bridges, and transaction lookups.
- `array` provides mapping, range mapping, reduction, indexing, concatenation, and length.
- `object` provides key and path access.
- `math` provides integer, floating-point, bitwise, comparison, and safe conversion functions.
- `types` injects ABI type guards and coercion functions as globals.

## Minimal read adapter

This adapter returns the native balance for an address:

```json
[
  "do",
  ["import", "herd", ["getNativeBalance"]],
  [
    "export",
    [
      "define",
      {
        "name": "nativeBalance",
        "parameters": [
          { "name": "account", "type": "address" },
          { "name": "chain", "type": "string" }
        ],
        "body": [
          "coerce",
          {
            "type": "uint256",
            "value": [
              "getNativeBalance",
              { "blockchain": "chain", "address": "account" }
            ]
          }
        ]
      }
    ]
  ]
]
```

## Action lifecycle

1. Search for an existing action or adapter before creating one.
2. Create a draft and validate its expression.
3. Publish the version that other tools and imports should use.
4. Simulate the action and inspect every resulting transaction.
5. Plan the first mainnet batch for the chosen wallet.
6. Submit the planned calls through that wallet, then record the hashes to advance the execution.

Mainnet and simulation are separate tracks on the same action execution. A simulation never broadcasts a transaction.

<Warning>
  Publishing and simulating are separate steps. Saved drafts cannot be imported, called, or started until their latest version is published.
</Warning>
